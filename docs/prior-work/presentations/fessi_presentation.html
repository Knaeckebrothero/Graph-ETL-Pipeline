Agent Enhancements: 'Fessi' Chatbot

Enhancing the 'Fessi' Chatbot

Our current LangGraph agent is powerful, but it's not being fully utilized. It's acting as a simple retrieval chain, which doesn't justify its stateful, multi-step potential.

Two Approaches Compared

🔗 Current

Simple Chain

The vector store is a linear chain. Simple RAG doesn't require or justify a stateful LangGraph agent.

User Query → Vector Search → Vague Answer
🧠 Proposed

Reasoning Engine

The Knowledge Graph justifies the agent, allowing for multi-step reasoning, disambiguation, and explicit process rules.

Query → Reason on Graph → Ask Question → Precise Answer

The Paint Can Example - Current Problem

Query: "Where can I dispose of an old paint can?"

Vector Store RAG (Current)

Retrieves conflicting chunks:

"...small amounts of dried paint can be disposed in residual waste..."
"...liquid chemicals and wet paint must be taken to chemical disposal site..."
"...the Building Supervisor (Room G.012) handles chemical disposal..."
Result: "You can put dried paint in residual waste, or take wet paint to the chemical disposal site, which is handled by the Building Supervisor."

❌ Problem: User must figure out which rule applies. Is it dried? Is it wet? Where exactly?

Step 1: Graph Schema Design

Defining the structure for our recycling knowledge graph

Node Types

Item (Paint, Birne, Battery, etc.)
Property (Form, Material, DangerLevel)
DisposalRule (Conditions, Requirements)
DisposalSite (Location, Hours, Accepts)

Relationships

🔹 HAS_FORM (Item → Property)
🔹 IS_A (Item → Category)
🔹 REQUIRES (Rule → DisposalType)
🔹 PROVIDED_BY (DisposalType → Site)
🔹 HAS_PROPERTY (Item → Property)
🔹 HAS_RULE (Category → Rule)
Example: (Paint:Item)-[:HAS_FORM {type:"liquid"}]->(LiquidPaint)-[:IS_A]->(Chemical)-[:HAS_RULE]->(ChemicalRule)-[:REQUIRES]->(SpecialistSite)
